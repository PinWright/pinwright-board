# Struct-only writes to exposed anim-node fields are overwritten at compile

A `UAnimGraphNode_*` field marked `PinShownByDefault` (e.g. `FAnimNode_TwoBoneIK::EffectorLocation`,
`JointTargetLocation`, `FAnimNode_SkeletalControlBase::Alpha`, `FAnimNode_ModifyBone::Translation`)
is owned by its input pin. `ReconstructNode` keeps the old pin's autogenerated default
(`EdGraphPin.cpp` `TransferPersistentDataFromOldPin`), and `AnimBlueprintCompiler.cpp` (~469-491)
pushes an unlinked exposed pin's default into the compiled node. A write to the struct alone
therefore reads back fine on the visual node but compiles to the pin value.

Fixed for `animation.authoring.add_two_bone_ik` / `add_modify_bone` under
`E-add-two-bone-ik-no-effector-location` #4 (`SyncSkeletalControlPinDefaultsFromStruct` in
`Handlers/Animation/AnimationAuthoringHandler_AnimBlueprint.cpp`). **Suspected, not verified**, for the
generic writers that go through `AnimGraphConstructionUtils::ApplyJsonValueToAnimNodeFieldByName`
(`animation.authoring.set_anim_graph_node_value`, `animation.authoring.add_graph_node` `properties`):
that path writes the runtime struct and was not seen to touch the pin.

Verify by setting `Alpha` / `EffectorLocation` on a TwoBoneIK through those verbs and reading the
pin's `DefaultValue` (or compiling and reading the generated node). If confirmed, write the pin
through the schema (`TrySetDefaultValue`) for any field that has a visible pin, as the typed helpers now do.
