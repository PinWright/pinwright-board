# MSIR emits GUID-only node references

MetaSound IR files contain nodes whose class reference is a bare GUID instead of a resolved class name:

```
node n3 = `None.8DABF36F4DD0C32A190157966FC9EE77`
```

The `None` prefix indicates the namespace/class lookup failed. Nodes like these can't be recompiled, validated, or understood semantically.

## Affected

43 of 143 MSIR files contain this pattern. Sample: `Game/Audio/MetaSounds/lib_DovetailClip/msir.txt`.

## Fix

`MSIRDecompiler.cpp` resolves each node's `ClassID` through the document dependency table; when the dependency's `FMetasoundFrontendClassName` has an empty Namespace and a GUID-shaped Name (UE's asset-class-GUID synthetic key), it builds an `FMetaSoundAssetKey` from the dependency's `Metadata`. The resolver tries three legs in order: (1) `IMetaSoundAssetManager::FindAssetPath` (exact `FMetaSoundAssetKey` = ClassName + Version); (2) a once-per-decompile asset-registry exact-key cache built from `UMetaSoundPatch` and `UMetaSoundSource` `FAssetData` parsed with `FMetaSoundAssetClassInfo::TryGetAssetKey`; (3) a **version-agnostic ClassName fallback** — the same asset-registry scan also populates a `FMetasoundFrontendClassName -> asset path` cache (via `TryGetAssetKey`, falling back to `TryGetAssetClassName` when the version tag is missing), looked up by `AssetKey.ClassName` only. Leg 3 is required because `FMetaSoundAssetKey` equality compares ClassName **and** Version (`MetasoundAssetKey.h`) while a dependency records the version the parent saw at authoring time, so a re-versioned referenced asset misses both exact-key legs even though it still exists; the asset-class GUID lives in `ClassName.Name` and is stable across versions. Native registry classes keep their namespace/name/version form. Unresolved cases (genuinely missing/external assets) keep the GUID fallback and append an `MSIR_UNRESOLVED_CLASS_REF` warning to `FMSIRResult::Warnings`. `AssetDumpCache.cpp::GetAspectVersion` bumps `msir.txt` to version 4 so dump-cache freshness cannot serve pre-fallback MSIR.
