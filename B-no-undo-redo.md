# BPIR operations don't respect Undo/Redo

`compile_bpir`, `insert_bpir_at_node`, `widget_import_xml`, `blueprint_graph_delete_node` and other mutating operations don't create UE undo transactions. Ctrl+Z does nothing after MCP operations.

**Fix:** Wrap each mutating MCP call in `FScopedTransaction`.

Added Modify() in 4 locations: ClearWidgetTree, RemoveWidgetSubtree, ProcessXmlNode (before AddChild/RootWidget assignment), and main handler (before MarkBlueprintAsStructurallyModified). Follows UE engine pattern from FWidgetBlueprintEditorUtils.
- `#6-returned-undo-still-broken` `OPEN` tester — Returned: `mcp__editor_automation__.call path="widget.import_xml" args={...}` undo still not working. Modify() calls don't capture ConstructWidget+AddChild changes — UE transaction system likely doesn't track new UObject creation within widget trees. Need manual rollback approach (collect created widgets, delete on undo) instead of relying on FScopedTransaction.
- `#7-moved-mark-outside` `IN-REVIEW` developer — Root cause: MarkBlueprintAsStructurallyModified was called INSIDE the FScopedTransaction scope, triggering a full BP recompile that invalidated transaction records. UE's NewObject with RF_Transactional (used by ConstructWidget) DOES track object creation in active transactions, and Modify() on parent/WidgetTree snapshots child lists. But the recompile reconstructed objects, making undo records point to stale pointers. Fix: moved MarkBlueprintAsStructurallyModified OUTSIDE the transaction scope using an inner { } block — transaction commits before recompile.
- `#8-returned-undo-rf-transactional` `OPEN` tester — Returned: undo still not working after moving MarkBlueprintAsStructurallyModified outside transaction. The transaction system's object-creation tracking via RF_Transactional+NewObject may not fully restore widget tree parent-child relationships on undo, or MarkBlueprintAsStructurallyModified outside the scope still invalidates records. Needs deeper investigation — possibly FCommandChange custom undo approach.
- `#9-proper-undo-api` `IN-REVIEW` developer — Two fixes: (1) Moved MarkBlueprintAsStructurallyModified back INSIDE FScopedTransaction scope — matches UE engine's PasteWidgets pattern; skeleton-only regen is safe inside transactions (confirmed no GC, no undo buffer flush). (2) Changed editor.undo handler from GEditor->Exec(World, "Undo") to GEditor->UndoTransaction() — proper API that directly invokes the transaction buffer.
