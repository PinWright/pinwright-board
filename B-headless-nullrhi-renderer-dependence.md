# Renderer-dependent verbs and tests under -NullRHI

Editor launches now take `mode: visible | offscreen | headless`, and `headless` adds `-NullRHI`. Without a renderer `RHIReadSurfaceData` returns zeros with success, `CaptureScene` is a no-op, `FWidgetRenderer` returns no target, `UMaterial` caches no shaders (`Material.cpp:2606`), `UNiagaraComponent::ActivateInternal` refuses to activate, and landscape edit layers never merge (`ALandscape::CanUpdateLayersContent`, `LandscapeEditLayers.cpp:7051`). Consequences before the fix: `render.capture_mesh` wrote an opaque-black PNG as success, `render.detect_z_fighting` reported `analyzedPixels:0`, `performance.run_benchmark` timed frames that render nothing, the other capture verbs failed with codes that did not name the cause (`BLANK_CAPTURE`, `CAPTURE_FAILED`, `THUMBNAIL_GENERATION_FAILED`, `MRQ_EXECUTOR_FAILED`), and every test driving them went red rather than skipping. Nine BPIR tests carried `EAutomationTestFlags::NonNullRHI`, so the engine silently dropped them from a headless queue although they need no renderer.

**Fix:** one predicate and one guard, `Utils/RenderingAvailability.h` (`PinWrightRendering::IsAvailable()` = `FApp::CanEverRender()`; `RequireRenderer(Ctx)` sends new `ERR_RENDERING_UNAVAILABLE` with data `{method, renderingModes:["offscreen","visible"]}`), a test seam `FScopedForceUnavailableForTesting`, and one test-side skip `PinWrightTestSkip::SkipIfRenderingUnavailable` (`Tests/TestSkipReporting.h`, reason `null-rhi`).
