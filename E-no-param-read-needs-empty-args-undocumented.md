# No-required-param read methods need `args={}` to execute; the omit-args=doc-fetch trap isn't surfaced on method/namespace pages

The `call` tool routes by argument shape: omit `args` entirely → wiki page; pass `args` (even `{}`) → execute (see `E-unify-discovery-omit-params`, the design rationale). For a read method that has **no required params** — e.g. `foliage.get_instances` with no filter (intent: "show me everything") — the natural call is "method name, nothing else." That shape is indistinguishable from a doc-fetch, so the agent silently gets the wiki page back instead of a result and has to re-issue the call with an explicit empty `args={}` to force execution.

This is a recurring first-contact tax on every no-required-params reader (`*.get_instances`, list/status/info-style verbs), not a one-off. The convention **is** documented — but only on the meta `wiki` overlay (`docs/wiki-src/wiki.md`, the "three modes" section: *"Methods with no required params still need `args={}` to disambiguate from a wiki view"*). An agent driving a foliage cleanup task navigates to the `foliage` namespace or the `foliage.get_instances` method page, never to the `wiki` meta page, so the warning is out of the line of sight at the exact moment it bites.

This is a discovery/docs gap, not a tool bug — the method works fine once `args={}` is passed. The fix is to surface the omit-args trap where no-required-params readers are discovered, so agents reach for `args={}` on the first call instead of after a wasted doc-fetch round-trip.

**What it should do:** Make the "no required params still needs `args={}` to execute (omitting `args` returns the wiki page)" note discoverable at the point of use — at minimum on the `foliage` namespace overlay (`docs/wiki-src/foliage.md`) near the `get_instances` mention, and ideally as a generic line the renderer or auto-content layer attaches to any method whose param spec has zero required params. The downstream wiki edit is out of scope for this audit (it's the wiki authoring process); this ticket just records the gap and names the overlay page.

**Docs page to improve:** `docs/wiki-src/foliage.md` (add a one-line "no-filter readback needs `args={}`" note); consider a generic treatment so every zero-required-param reader inherits it rather than per-namespace duplication.
