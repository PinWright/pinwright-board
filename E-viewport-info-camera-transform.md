# system.inspect.get_viewport_info returns only pixel dimensions, not the camera transform

`system.inspect.get_viewport_info` returns only the active level viewport's pixel `width`/`height` (`EnvironmentHandler.cpp:1162-1181` — sets only `width`, `height`, `success`). It does not expose the camera location/rotation/FOV. There is no read-back of the editor camera anywhere, so an agent can't confirm where the viewport is looking before or after a screenshot. This compounds the write-side `editor.set_camera` redraw gap (`B-set-camera-no-viewport-redraw`): with no camera read-back, a stale/unmoved capture can't be diagnosed, forcing blind screenshot iteration. Distinct from `F-editor-viewport-screenshot` (capturing the viewport) — this is reading the camera state.

Add `cameraLocation`, `cameraRotation`, and `fov` to the response.

**Workaround:** none for read-back — infer camera state indirectly by screenshotting and eyeballing the frame.
**Fix:** location + rotation come from the symmetric read partner of the setter `set_camera` already uses: `UUnrealEditorSubsystem::GetLevelViewportCameraInfo(OutLoc, OutRot)`. For FOV, resolve the active perspective `FLevelEditorViewportClient` (via `GEditor->GetActiveViewport()->GetClient()` cast) and read `FEditorViewportClient::ViewFOV` (with `GetViewLocation()`/`GetViewRotation()` as a fallback). Add the three fields alongside the existing `width`/`height`.
