# Composite material nodes are decompile-only — compile rejects the output

`UMaterialExpressionComposite` (the result of UE's "Collapse Nodes"
group-box feature in the Material editor) decompiles to MGIR as a
`subgraph "Name" { ... }` block. **The MGIR compiler hard-fails
on that syntax** with `MGIR_COMPOSITE_NOT_SUPPORTED` at
`MGIRCompiler.cpp:587-590`.

Any material that has had Collapse Nodes applied in the editor
produces MGIR text that immediately fails to recompile. This is
one of the most actively used Material editor organization
features — large materials are routinely collapsed into named
sub-blocks for readability.

The plugin docs (`material.mgir.md`) acknowledge this:
"Decompiled composite graphs appear as subgraph; compiling that
text fails."

## Repro

1. Pick any Material with a composite group in the editor.
2. `call("material.decompile_mgir", { "assetPath": "..." })` →
   includes `subgraph "..." { ... }` blocks.
3. `call("material.compile_mgir", { "mgir": "..." })` →
   `MGIR_COMPOSITE_NOT_SUPPORTED` error.

## Fix

Two paths:

1. **Inline at decompile (cheap):** flatten composite contents into
   the parent graph during decompile. Lose the grouping but the
   text round-trips. Mirrors how BPIR handled `K2Node_Composite`
   inlining (`B-bpir-composite-inline-name-lost`).
2. **Round-trip composite (expensive):** add MGIR compiler support
   for the `subgraph "Name" { ... }` form, constructing
   `UMaterialExpressionComposite` and recursively compiling its
   inner expressions.

Option 1 unblocks compile but loses editor organization. Option 2
is the full fix. Decision-point: are composites primarily authored
in the Material editor (need to preserve them) or generated by
tooling (don't care)?

- `#1-initial-spec` `OPEN` reporter — MGIR coverage parity audit. Decompile emits `subgraph "Name" { ... }`, compile hard-errors `MGIR_COMPOSITE_NOT_SUPPORTED` (`MGIRCompiler.cpp:587-590`). Recompiled that MGIR into `/Game/App/UI/Test/M_McpVerifyTemp_B_mgir_composite_subgraph_compile_fail_dst` via `material.compile_mgir` and observed `blocksCompiled:1`, `expressionsCreated:1`, no `MGIR_COMPOSITE_NOT_SUPPORTED`; deleted both temp assets afterward.
