# landscape.create_procedural_terrain's docs describe the Ed Mode brush, not the verb

`landscape.create_procedural_terrain` writes exactly one layer channel: its only write is the
single-layer `SetAlphaData`
(`Source/PinWright/Private/Handlers/Environment/LandscapeHandler.cpp:3416`), which on UE 5.8 subscripts
only `LayerDataPtrs[UpdateLayerIdx]` (`Engine/Source/Runtime/Landscape/Private/LandscapeEditInterface.cpp:2324-2328`).
Siblings lose weight only through the edit-layer merge's final weight-blending pass, and only when
they are `FinalWeightBlending` (the handler's own correction comment, `LandscapeHandler.cpp:3461-3465`;
the wiki's parenthetical at `docs/wiki-src/landscape.md:255`, and the blend-method paragraph at `:259`).

Landscape Ed Mode's brush is a different operation: `FLandscapeToolStrokePaint::GetAffectedTargetLayersForTarget`
(`Engine/Source/Editor/LandscapeEditor/Private/LandscapeEdModePaintTools.cpp:198-224`) enumerates the
target's blend group and writes every sibling down (inverted, `:217`; looped in `Apply` at `:315`),
by default (`ExclusiveRequiresNoCtrl`, `LandscapeEditorObject.cpp:368`).

Three sites still attribute the brush's mechanism to the verb:

1. `docs/wiki-src/landscape.md:257` — *"it is the same thing Landscape Ed Mode's paint brush does:
   the engine's own stroke enumerates the target layer's blend group and writes every member of
   it"*, and *"painting one layer over the full extent and then a second one on top ... erases the
   first everywhere they overlap"*.
2. The `REGISTER_RPC_HANDLER` description (`LandscapeHandler.cpp:2783`) — *"never by painting one
   layer over the full extent and then another"*, the same erase premise in the tool description
   every client lists.
3. The census comment at `LandscapeHandler.cpp:3271-3276` — *"The engine's own paint stroke ...
   writes EVERY member of it ... So siblings losing weight INSIDE the region is the engine's
   normalization working as designed"*.

The consequence: the write does not drive a sibling down, so a second paint over a region where
another layer already holds weight leaves both layers carrying weight there (normalized against
each other by the merge when both are weight-blended), instead of the second replacing the first as
the brush would. Measured on a pre-`weightBlended` build: painting `Grass` 1.0 over the full extent
left `Rock` at `texelsWithWeight 2601 -> 2601`; the step that made a layer own a region was `Grass 0`
**then** `Rock 1.0`. The docs never state that step and assert it is unnecessary.

**Fix:** at all three sites, describe the verb: one channel per call; sibling weight changes only
through the merge's normalization of `FinalWeightBlending` layers, which shares weight rather than
erasing it; Ed Mode's brush is a different (blend-group, exclusive) operation; to make a layer own a
region through this verb, paint its siblings to `strength: 0` over that region first. Keep
`landscape.md:255` and `:259` as they are.

**Acceptance:** `landscape.md` and the `create_procedural_terrain` tool description no longer say the
verb does what the Ed Mode brush does or that a second paint erases the first; both state the
paint-siblings-to-0 step; the `:3271-3276` comment no longer attributes the brush's blend-group write
to this verb.
