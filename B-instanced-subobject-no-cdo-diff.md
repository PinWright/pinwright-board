# Instanced subobject recursion inlines all fields with no CDO diff or flag filter

[B-asset-dump-instanced-subobjects-not-recursed](B-asset-dump-instanced-subobjects-not-recursed.md) (DONE) added `ExpandInstancedSubobject` → `StructToJsonObject` so `Instanced` UObject sub-properties get inlined instead of emitting a path string. That recursion is correct in intent, but `StructToJsonObject` (`Utils/PropertyExport.cpp:360`) walks **every** field of the expanded subobject and emits all of them — with **no diff against the subobject's own class CDO** and **no `CPF_Edit` / `CPF_Transient` filtering**. Once an instanced subobject is admitted at the top level, its entire state dumps verbatim, defaults included.

The sparse-diff promise (`actor.describe` wiki: "sparse modified component properties") therefore only holds at the *top* property level — `BuildSparsePropertyDiffJson` (`Utils/PropertyDiff.cpp`) correctly skips properties `Identical` to the archetype, but the moment an instanced ref is admitted the inner walk is non-sparse.

**Concrete blowup:** `UText3DComponent`'s five `*Extension` properties are `Instanced` (`Text3DComponent.h:452-468`); each component's transient dynamic material instances (`/Engine/Transient.MID_M_Text3DOpaqueUnlit_*`) never equal the archetype, so the top-level diff always admits `MaterialExtension`, and the full extension object (every layout / geometry / rendering / material field, defaults and all) dumps. A PhotoInspection "bucket" actor with ~13 Text3D label components multiplies this: `actor.describe` returns **633 KB**, `blueprint.scs.get` **71 KB** — both spill to file, masking the over-serialization rather than fixing it. The five `RingMarkerComponent`s the caller usually wants are a sliver of that.

**Repro:** `actor.describe {actorName:"B_BucketUp_C_*"}` (a bucket: 1 StaticMesh + ~13 Text3DComponent + 5 RingMarkerComponent) → 633 KB spill. Same actor's BP via `blueprint.scs.get` → 71 KB spill.

**Related gap:** `BuildSparsePropertyDiffJson` (the `actor.describe` path) does **not** consult the `IsKnownOversizedProperty` denylist (`Utils/PropertyExport.cpp`, from [E-asset-dump-oversized-fields](E-asset-dump-oversized-fields.md)) that `BuildClassPropertyJson` (dump) and `AddOverriddenProperties` (scs) do — so `actor.describe` also dumps the three known-huge props (`ImpulseResponse`, `AggGeom`, `PerInstanceSMData`) in full.

**Fix:** Make `StructToJsonObject` (or `ExpandInstancedSubobject`) recurse with a defaults baseline — compare each expanded field against `Subobject->GetClass()->GetDefaultObject()`, the same diff the top-level loop already runs against the archetype — and apply the same `CPF_Edit` / `CPF_Transient` flag filtering the outer loop uses. Separately, route `BuildSparsePropertyDiffJson` through the oversized-property denylist. The existing depth cap (`InstancedSubobjectMaxDepth = 3`) bounds object-graph depth, not per-level field breadth, so it does not help here.
