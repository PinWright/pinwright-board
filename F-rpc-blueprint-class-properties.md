# Inheritance-tagged CDO property diff (`inherited_from` / `is_overridden_locally`) is dump-only; no live RPC exposes it

`PropertyUtils::BuildClassPropertyJson(CDO, ParentCDO)` (Source/EditorAutomationRpcGateway/Private/Utils/PropertyUtils.cpp:2026) walks every reflected `FProperty` on a CDO, calls `ExportPropertyToJsonValueWithInheritance` per property to attach `type`, `value`, `inherited_from` (set when the property's `OwnerClass` is an ancestor of the asset class — the source class name), `is_overridden_locally` (set only when the value differs from the parent CDO under `PPF_DeepComparison`, with a UserWidget compiler-managed-flag exception), and `flags`, and returns a sparse object containing only properties that locally override the parent — the schema-v2 / -v3 sparse diff. It is invoked exclusively from `AssetDumpHandler.cpp` (lines 473, 485, 498, 505, 511, 517, 528, 615, 630, 650, 656, 698, 1666) for `properties.json` / `world_settings.json` sidecars and from tests; no live RPC handler calls it.

The closest live surfaces fall short:
- `blueprint.inspect` (BlueprintInspectHandler.cpp) returns metadata, variables, functions, events, components, graphs, references, and warnings. It surfaces zero CDO property *values* — variables only carry name/type/default-string at best, not the per-property inheritance source or the override-vs-parent verdict.
- `property.list` (UtilityPropertyHandler.cpp:1115) emits a flat `{name, value, defaultValue, hasDefaultValue, isOverridden, metadata, flags}` per property. The `isOverridden` field compares against the *immediate* class default, never names the source class for inherited fields, and the response is full (not sparse) — every reflected property is included, defeating the dump's signal-vs-noise design. There is no `inherited_from` attribution.
- `blueprint.set_default` is a write verb that returns one post-compile value; not an enumeration surface.

Grep confirms: no other handler in the source tree references `BuildClassPropertyJson`, `inherited_from`, or `is_overridden_locally`. This violates the dump-parity policy: anything an asset dump emits must also be reachable via a live RPC. Authoring agents that mutate a CDO via `blueprint.set_default` and want to verify which fields end up locally overridden vs inherited (and from which ancestor class) currently have no live path — they must trigger a full `asset.dump` round-trip just to read back the inheritance-tagged diff for the asset they just edited.

**Fix:** Widen `blueprint.inspect` additively rather than adding a sibling `blueprint.class_properties` RPC. Rationale: `blueprint.inspect` is already the umbrella "describe a Blueprint" verb (its summary lists metadata + variables + functions + events + components + graphs + references + warnings as its scope), the wiki advertises it as the introspection entry point, and the inheritance-tagged property block is the natural next category to live alongside `variables`. A sibling RPC would split a single-purpose surface across two endpoints with duplicate routing and wiki entries, mirroring the rationale in `F-rpc-blueprint-describe-struct.md`.

Implementation shape:
1. Add an opt-in `RPC_PARAM_DEF("includeProperties", "bool", "Include sparse CDO property diff (inherited_from / is_overridden_locally tagged) — schema v2/v3, mirrors asset.dump properties.json", "false")` parameter to `blueprint.inspect`. Default `false` keeps the existing response shape and payload size unchanged for current callers.
2. When the flag is true, resolve `BP->GeneratedClass->GetDefaultObject()` for the child CDO and `BP->GeneratedClass->GetSuperClass()->GetDefaultObject()` for the immediate generated superclass CDO when available; then call `BuildClassPropertyJson(CDO, ParentCDO)` and attach the result under a new `properties` key on the response. This must match `AssetDumpHandler` sparse Blueprint properties behavior, not the `nativeParentClass` metadata walk. Skip stubs / `BLUEPRINT_NOT_FOUND` paths unchanged.
3. No new public helper is needed — `BuildClassPropertyJson` is already exported via `EDITORAUTOMATIONRPCGATEWAY_API` in PropertyUtils.h:58. Reuse as-is to keep one source of truth with the dump.
4. Update `docs/wiki/blueprint.md` to document the new flag under the existing `blueprint.inspect` section, noting the schema parity with `properties.json`, the `inherited_from` / `is_overridden_locally` semantics, and the recommended use case (post-`blueprint.set_default` readback without a full dump round-trip).
5. Add a regression test in `Source/EditorAutomationRpcGatewayTests/Private/Blueprint/` that creates parent and child Actor Blueprints, changes an inherited native property on the child CDO, calls `blueprint.inspect` with `includeProperties=true`, and asserts the response carries the expected `inherited_from` source class name plus `is_overridden_locally=true` on the child override while omitting an unchanged inherited property (sparse diff and immediate-parent baseline verification).
