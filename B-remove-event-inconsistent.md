# `blueprint_remove_event` inconsistent behavior

`remove_event` sometimes reports idempotent "not present" for events that exist. Graph search fallback was added but duplicates still occurred. Possible issue: entry node deleted but connected subgraph left behind.

## History
- `#1-initial-repro` `OPEN` reporter — Duplicate OnDroneArmedEvent and ShowPopup events appeared despite remove_event calls between compilations.
- `#2-expanded-graph-search` `IN-REVIEW` developer — Expanded graph search to find both `UK2Node_CustomEvent` and `UK2Node_Event` overrides (matched by `EventReference.GetMemberName()`). Added FunctionGraphs fallback for override functions. Added BFS exec-chain cleanup: walks downstream exec pins from event root to collect and remove all body nodes. Added `removedNodeCount` to response JSON. Three tests added: standard event removal, custom event removal, idempotent no-op.
- `#3-verified-remove-event` `DONE` tester — Verified: compiled TestRemoveMe event with PrintString body on W_McpTestTemp, then remove_event returned removedNodeCount: 2 (entry + body). blueprint_inspect confirms event gone from events list. BFS exec-chain cleanup works.
- `#4-regression-bound-events` `OPEN` reporter — **Regression**. Session on `W_MyReplayListItem` cloned from `W_MyTrackListItem`: after `mcp__editor_automation__.call path="widget.remove_widget" args={...}` removed `RenameButton`, `RenameButtonHovered`, `UploadButton`, `UploadButtonHovered`, `DeleteButtonHovered`, each follow-up `mcp__editor_automation__.call path="blueprint.remove_event" args={...}` with the display title (e.g. `"On Clicked (RenameButton)"`) returned `{removedNodeCount: 0, note: "Event not present; treated as removed (idempotent)."}` for all 5. Immediately after, `mcp__editor_automation__.call path="blueprint.graph.find_nodes" args={"query":"RenameButton"}` located all 5 as live `K2Node_ComponentBoundEvent` nodes with the exact titles I'd just been told were absent. Had to delete each by `nodeId` via `mcp__editor_automation__.call path="blueprint.graph.delete_node" args={...}`. The DONE-fix matcher appears to miss `K2Node_ComponentBoundEvent` nodes when the source component has been removed from the widget tree — the component reference is stale but the event node persists with its display title intact. Repro: duplicate any widget BP containing component-bound clicks → remove the components via `mcp__editor_automation__.call path="widget.remove_widget" args={...}` → call `mcp__editor_automation__.call path="blueprint.remove_event" args={...}` with the display title → false idempotent response while the node is still in the graph.
- `#5-bound-event-branches` `IN-REVIEW` developer — Added dedicated `UK2Node_ComponentBoundEvent` and `UK2Node_ActorBoundEvent` branches in the ubergraph loop before the generic `UK2Node_Event` branch in `BlueprintEventHandler.cpp`. Matches against `GetNodeTitle(FullTitle)`, rebuilt `"Delegate (Component)"` form, bare `DelegatePropertyName`, and `CustomFunctionName` — covers display-title input even when the source component has been removed. Stale `ComponentPropertyName` is safe (FName read doesn't require the property to resolve). Added include guards for `K2Node_ComponentBoundEvent.h` / `K2Node_ActorBoundEvent.h`.
- `#6-verified-bound-event-remove` `DONE` tester — Verified: created `W_McpVerify_RemoveEvent` with `Button` child `TestBtn1`, compiled BPIR `entry widget_event TestBtn1.OnClicked() {}` to produce a `K2Node_ComponentBoundEvent` with title `"On Clicked (TestBtn1)"`, then removed `TestBtn1` via `mcp__editor_automation__.call path="widget.remove_widget" args={...}`. `mcp__editor_automation__.call path="blueprint.graph.find_nodes" args={...}` confirmed the bound-event node persisted after component removal. Calling `mcp__editor_automation__.call path="blueprint.remove_event" args={"eventName":"On Clicked (TestBtn1)"}` returned `removedNodeCount: 1` (no idempotent note); follow-up `mcp__editor_automation__.call path="blueprint.graph.find_nodes" args={...}` returned `matchCount: 0`. Display-title matching for component-bound events with removed source components works.
