# Niagara compile diagnostics read a cvar that does not exist, so compileDeferredOnLoad is always false

`NiagaraDecompileHelpers::IsNiagaraOnDemandCompileEnabled()` (`NiagaraDumpBuilder.cpp`) looked up `fx.Niagara.OnDemandCompile`. No supported engine registers that name: UE 5.3-5.8 all register `fx.Niagara.OnDemandCompileEnabled` (`NiagaraSystem.cpp`, 5.8 `:198-204`; default `1` on 5.3-5.5, `2` on 5.6+). `FindConsoleVariable` returned null, the helper returned `false`, and the three live compile builders (`BuildCompileDiagnosticsJson`, `BuildEmitterCompileDiagnosticsJson`, `BuildScriptCompileDiagnosticsJson`) always published `compileDeferredOnLoad: false` and never raised `COMPILE_DEFERRED_ON_LOAD`, on every engine, while the editor was in fact deferring compile on load. Consumers: `niagara.inspect` (compile block) and `niagara.validate` (promotes the issue to a warning).

The same wrong name made four regression tests skip on every engine with `reason=cvar-absent`, so the defect was never measured: `PinWright.Niagara.DumpCompile.DeferredFlag`, `.UninitializedSystem`, `.UninitializedEmitter`, `PinWright.niagara.decompile_nir.CompileStateStaleAnnotation` (suite log `Saved/PinWright/test-runs/499a9295d82f445ba80a44ebe091bbb9/automation.log`). The tests also restored the cvar through `GetBool()`, which would have written `1` over the 5.6+ default `2`.

**Fix:** read `fx.Niagara.OnDemandCompileEnabled` with the engine's own predicate from `UNiagaraSystem::PostLoad` (`Mode != 0 && (GIsEditor || Mode == 2)`); tests use the real name and restore the exact original string.

## History
- `#1-cvar-name-never-registered` `OPEN` reporter — Four Niagara compile-state tests skip on UE 5.8 with `fx.Niagara.OnDemandCompile CVar is not registered`. Grep of `C:\UE_5.3`..`C:\UE_5.8` `Engine/Plugins/FX/Niagara` finds only `fx.Niagara.OnDemandCompileEnabled`; production `IsNiagaraOnDemandCompileEnabled()` uses the same wrong name, so `compileDeferredOnLoad` is always `false` and `COMPILE_DEFERRED_ON_LOAD` never fires on any engine.
- `#2-read-real-cvar` `IN-REVIEW` developer — `NiagaraDumpBuilder.cpp` `IsNiagaraOnDemandCompileEnabled()` now reads `fx.Niagara.OnDemandCompileEnabled` and returns `Mode != 0 && (GIsEditor || Mode == 2)`; the `COMPILE_DEFERRED_ON_LOAD` message names the real cvar. `TestNiagaraDumpCompileDeferred.cpp` (3 tests) and `TestNIRDecompiler.cpp` (`CompileStateStaleAnnotation`) look up the real name and restore via `GetString()`/`Set(*Original)`. Stale name also fixed in `NIRTextEmitter.cpp` comment, `docs/arch.md`, `docs/wiki-src/niagara.compile-state.md`, `docs/wiki-src/niagara.md`; the declaration comment in `NiagaraDecompileHelpers.h` still names the old cvar (header not edited in this change). Behaviour change: `niagara.validate` now carries a `COMPILE_DEFERRED_ON_LOAD` warning in any editor with the default cvar. Not yet built or run; needs the four tests to run their assertions on 5.8.
- `#3-gate-deferred-issue` `IN-REVIEW` developer — The cvar is on in every default editor, so the #2 fix made `COMPILE_DEFERRED_ON_LOAD` appear on every `niagara.validate` call. The issue exists to tell a caller that compile state it is reading is post-load, not a fresh compile, so it now fires only when that is true for the asset. Two helpers in `NiagaraDumpBuilder.cpp` do this: `AddCompileDeferredIssueIfStale` and `ScriptsHaveNonTerminalCompileStatus`. System: the issue fires when `!IsSystemReadyToRunWithoutLoading`, which covers PostLoad's pending on-demand request and a system that never compiled. Emitter and script assets: it fires when any present script is not UpToDate* or NCS_Error. `compileDeferredOnLoad` still reports the session fact unconditionally. `NiagaraDecompileHelpers.h` comment fixed. New test `PinWright.Niagara.DumpCompile.DeferredIssueClearsAfterCompile` force-compiles a duplicated SimpleExplosion and asserts the field is true and the issue absent. The existing DeferredFlag case A still expects the issue on a never-compiled transient system. Documented in `docs/wiki-src/niagara.compile-state.md`.
- `#4-never-compiled-system-is-stale` `IN-REVIEW` developer — The full offscreen suite (`test-runs/7b2d4d4c5a494988a2c90b28389aad29`) failed `DeferredFlag` case A: the #3 gate used only `IsSystemReadyToRunWithoutLoading`, which reads a never-compiled, emitter-less transient system as ready (it has no pending request and no emitters to be not-ready). The gate was wrong, not the test. The system gate now also treats the system's own spawn/update scripts at a non-terminal `GetLastCompileStatus()` as stale; emitter-script statuses are still excluded. `DeferredIssueClearsAfterCompile` passed in that run and still covers the compiled direction. It now owns its fixture through `TStrongObjectPtr` plus `CleanupTestAsset` (`NiagaraEditTestUtils::DuplicateFixtureSystemWithEmitters`) instead of a raw `AddToRoot`, which restores the `infra.contract.AddToRoot.ScopedFixtureOwnership` ratchet count of 2 for that file.
