# Starting the editor can build the project, and the caller is never told

UE 5.8, host `X:\src\unreal\unreal-fpv-new`, plugin `8748c637`. `mcp__pinwright__editor_start {map: /Game/System/FrontEnd/Maps/L_Core, unattended_script: true}`
returned `{success: true, pid, commandLine, elapsedSeconds: 124.4}`. `Saved/Logs/PDS.log` shows that during
that start the editor ran `Build.bat Development Win64 -Project=... -TargetType=Editor` (UBT, 24 actions,
`Result: Succeeded`, 46 s), recompiling `Plugins/App/Source/App/Api/*` and `Acceptance/*`. Other agents
were editing those files in the same checkout at the time, and the task rules said not to build. The
rebuild happens because the engine's "modules are out of date, rebuild?" prompt is auto-accepted under
`-RunningUnattendedScript`. The response gives no hint that a build ran.

Why it matters: in a shared checkout, a start that only means "restart the editor" can compile someone
else's half-finished code into the loaded DLL. A failing build would make the start look like a hang or a crash.

**Fix:** detect stale modules before spawning (compare module timestamps, or pass `-NoCompile`/equivalent
so the editor refuses rather than builds). Report `modulesRebuilt: true` plus the UBT result in the
response, and offer an explicit `allow_build` flag (default false for unattended starts).

## History
- `#1-start-rebuilt-app-module` `OPEN` reporter - UE 5.8, host `X:\src\unreal\unreal-fpv-new`, plugin `8748c637`. Noticed after the fact in the log; the build succeeded, so no work was lost, but the no-build rule was broken without anyone deciding to break it.
- `#2-skipcompile-on-visible-launch` `IN-REVIEW` developer - The cause is not the "modules out of date" prompt being auto-accepted. The engine runs its whole startup module check only when not `-unattended` (`LaunchEngineLoop.cpp:6581`), and the host ships `bForceCompilationAtStartup=True` in `Config/DefaultEditorPerProjectUserSettings.ini`. When that setting is on, `CompileGameProject` runs on EVERY non-unattended start without asking (`:6637-6640`, `:6745`): UBT with `-TargetType=Editor -NoEngineChanges`, which matches the reporter's log. The native `FPlatformMisc::MessageBoxExt` prompt does not honour `-RunningUnattendedScript` anyway. So only `mode: visible` launches were affected. Offscreen/headless and `editor_run_tests` carry `-unattended` and never compile; a recent suite log confirms no UBT build line. On Linux the same path is what fails with `FailedDueToEngineChange`, because UBT runs without `-UsePrecompiled`. Fix: `build_editor_command` appends `-SKIPCOMPILE`, the only switch that clears the setting, to every visible launch unless the new `allow_build: true` is passed. `editor_start`/`editor_restart` accept `allow_build` (visible only). On offscreen/headless, or when it is not a bool, it is refused with `INVALID_ARGUMENTS` (`param: allow_build`); restart refuses before quitting. The result carries `startupCompile: "skipped" | "allowed"`. Not done: `modulesRebuilt`/UBT-result log parsing for `allow_build: true`, which stays the caller's explicit opt-in, and a pre-spawn BuildId check. `-SKIPCOMPILE` does not cover missing or wrong-BuildId binaries; on a visible launch the engine still shows its native rebuild prompt for those. Files: `Content/Python/mcp_proxy.py` (`_SKIP_STARTUP_COMPILE_FLAG`, `build_editor_command(allow_build=)`, `_allow_build_error`, start/restart schema + wiring), `Content/Python/tests/test_mcp_proxy_editor_start.py`, `docs/wiki-src/mcp-transport.md`, `CHANGELOG.md`. Tests (python): `BuildEditorCommandTest.test_visible_skips_the_startup_compile_unless_allow_build`, `.test_windowless_never_carries_skipcompile`, `ProxyEditorStartTest.test_visible_start_with_a_map_skips_the_startup_compile`, `.test_allow_build_leaves_the_startup_compile_to_the_engine`, `.test_result_reports_which_startup_compile_policy_applied`, `.test_bad_allow_build_is_refused_before_anything_is_spawned`, `ProxyEditorRestartTest.test_allow_build_is_forwarded_to_the_start_half`, `.test_windowless_allow_build_is_refused_before_the_quit`. Counterfactual run (append disabled in a copy of the tree): 6 tests fail, namely `test_visible_skips_the_startup_compile_unless_allow_build`, `test_visible_start_with_a_map_skips_the_startup_compile`, and the four exact-argv visible tests now pinning `-SKIPCOMPILE`. Full engine-python suite: 451 run, OK, 5 skipped. Not verified live: no editor was started.
- `#3-review-fixes` `IN-REVIEW` developer - Review follow-up. In `editor_start`, `allow_build` is now validated right after `timeout` and before `slot_wait` and the editor-process and capacity guards, so a bad call fails at once instead of after a wait of up to 3600 s. `startupCompile` is now computed from the final argv: it reads `skipped` when `-SKIPCOMPILE` or `-unattended` appears anywhere, including in `extra_args`. New tests: `ProxyEditorStartTest.test_bad_allow_build_is_refused_before_the_slot_wait_and_guards` and `.test_startup_compile_reads_the_final_argv`.
