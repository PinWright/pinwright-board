# `animation.authoring.get_animation_info` on a BlendSpace emits only {assetType, skeletonPath, numSamples} — no samples/axes parity with asset.dump

`get_animation_info` is documented as the "introspection dual" used to "confirm the asset shape" after authoring (see `animation.authoring.md`, *Inspect-after-mutate*). For a `UAnimSequence` it returns a rich shape (`duration`, `numFrames`, `frameRate`, `frameRateRational`, `additiveType`, `rawTrackCount`, `skeletonAssetPath`, …). But the `UBlendSpace` branch (`AnimationAuthoringHandler_Sequence.cpp:1842-1850`) emits only three fields:

```
{"animationInfo":{"assetType":"BlendSpace1D","skeletonPath":"/Game/Characters/Echo/Meshes/Echo_Skeleton.Echo_Skeleton","numSamples":3},"success":true,"message":"Animation info retrieved"}
```

There is no per-sample list (animation path + coordinate), no axis config (name / min / max / grid), and no interpolation. After authoring a blend space via `create_blend_space_1d` → `set_axis_settings` → `add_blend_sample` (×N), the only way to verify the round-trip — *which clip landed at which coordinate on which axis* — is to fall back to the read-only `asset.dump` sidecar `blend_space.json`, which `BlendSpaceDumpBuilder::BuildBlendSpaceJson` (`Handlers/Asset/BlendSpaceDumpBuilder.cpp`) emits with full fidelity:

```
"axes":[{"displayName":"Speed","gridNum":4,"max":600,"min":0}, …],
"samples":[
  {"animation":"/Game/Characters/Echo/Animations/Idle.Idle","rateScale":1,"x":0,"y":0},
  {"animation":"/Game/Characters/Echo/Animations/Idle_Long.Idle_Long","rateScale":1,"x":250,"y":0},
  {"animation":"/Game/Characters/Echo/Animations/Jog_Fwd.Jog_Fwd","rateScale":1,"x":600,"y":0}
],
"interpolation":[{"interpolationTime":0,"interpolationType":"BSIT_SpringDamper"}, …]
```

So the sample coordinates, axis ranges, and clip-to-position mapping are **exclusive to the dump** — unreachable through the live introspection RPC. This is the same no-exclusive-dump-fields parity gap that `E-rpc-animation-extend-get-animation-info` (DONE) fixed for the `UAnimSequence` branch, repeated here for the `UBlendSpace` branch. `numSamples` confirms *how many* samples exist but not *which* or *where*, so the documented inspect-after-mutate verification loop cannot be completed from `get_animation_info` alone for blend spaces. The call is not wrong (the count is accurate, no crash, valid JSON) — it is too thin to verify the very assets `add_blend_sample` / `set_axis_settings` author.

**Workaround:** read the `asset.dump` `blend_space.json` sidecar (`samples[]` + `axes[]`) for the per-sample coordinate mapping.

**Fix:** Additively extend the `UBlendSpace` branch of `get_animation_info` to emit the dump's `samples[]` (animation path + x/y + rateScale) and `axes[]` (displayName + min/max + gridNum), reusing the public accessors the dump already uses (`BlendSpace->GetBlendSamples()`, `BlendSpace->GetBlendParameter(i)`) — ideally by delegating to `BlendSpaceDumpBuilder::BuildBlendSpaceJson` so the live shape matches the sidecar. Keep `assetType`, `skeletonPath`, and `numSamples` for backward compatibility.
