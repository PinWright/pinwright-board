# Stock SpawnRate fixture loaded from a path that never existed

Seven tests skip with `PINWRIGHT_ASSERTIONS_SKIPPED` on UE 5.8 (suite log
`Saved/PinWright/test-runs/499a9295d82f445ba80a44ebe091bbb9/automation.log:43230-43708`,
preceded by `LogUObjectGlobals: Warning: Failed to find object 'NiagaraScript /Niagara/Modules/Spawn/SpawnRate.SpawnRate'`):

- `PinWright.niagara.decompile_nir.OverrideLiteralFloat` / `OverrideLinkedParam` / `OverrideDynamicInput` / `OverrideRecursionDepth`
  (`Tests/Niagara/TestNIRDecompiler.cpp:998`, helper `LoadNirOverrideTestModuleScript`)
- `PinWright.niagara.decompile_nir.GraphLinkCoverage` (`Tests/Niagara/TestNIRGraphLinkCoverage.cpp:45`)
- `PinWright.niagara.move_module.RelayoutsNodePosY` (`Tests/Niagara/TestNiagaraMoveModule.cpp:112`)
- `PinWright.niagara.reset_module_input.DynamicInputResetKeepsStackChain` (`Tests/Niagara/TestNiagaraResetModuleInput.cpp:187`)

Root cause: all four sites hardcode `/Niagara/Modules/Spawn/SpawnRate.SpawnRate`. The
asset lives at `Engine/Plugins/FX/Niagara/Content/Modules/Emitter/SpawnRate.uasset` on every
engine 5.3-5.8 (checked `C:\UE_5.3`..`C:\UE_5.8`); `Modules/Spawn/SpawnRate.uasset` exists on
none. The path was wrong since the first commit that carries it (`8748c637`), so these tests
have never run their assertions. The other 13 SpawnRate call sites in `Tests/Niagara/`
(e.g. `TestNiagaraSetModuleInput.cpp:161`, `TestNiagaraGetModuleInputs.cpp:44`) already use
the correct `/Niagara/Modules/Emitter/SpawnRate.SpawnRate` and run. No production code,
wiki-src page, or generated wiki page references the wrong path.

- `#5-nir-link-coverage-assertions` `IN-REVIEW` developer — `PinWright.niagara.decompile_nir.GraphLinkCoverage` failed on its first real run (`test-runs/7b2d4d4c5a494988a2c90b28389aad29/automation.log`) because of two defects in the test. The NIR was correct in both cases. (a) `TestNIRGraphLinkCoverage.cpp:108` required `graph ParticleSpawn {`. `EmitScriptGraphScope` names the graph after the script's own usage (`NIRTextEmitter::FormatUsageName(Script->GetUsage())`), and the seed emitter (SimpleExplosion) spawns with interpolation: its package's name table carries `ENiagaraScriptUsage::ParticleSpawnScriptInterpolated`, and `NiagaraEmitter.cpp:1237` sets that usage when `UsesInterpolatedSpawning()`. So the header is `graph ParticleSpawnInterpolated {`. The other five headers were present, which rules out a missing scope. The assertion now accepts either header. (b) `:119` counted `"\nlink "`. Every graph scope sits inside a `system` / `emitter` scope, so each link line is indented (`GNIRIndentSpaces = 4`, `NIRTextEmitter.cpp:24`) and the anchor could never match (`got 0`). The test now counts lines whose trimmed start is `link `, and the orphaned `Utils/StringUtils.h` include is removed. `PinWright.niagara.decompile_nir.OverrideRecursionDepth` passed while measuring nothing (`Could only author 1-deep chain`, `automation.log:43583`). It looked for the next input as a pin on the dynamic-input call node, where `Module.*` inputs have no pin. It now takes the first float input from `NiagaraEdit::EnumerateModuleStackInputs`, the same fix `#4` made in the reset test, and asserts `ChainDepth > 32` unconditionally: a shallow chain fails instead of warning. The guard is emitted only because nested dynamic-input overrides now render (`B-nir-stack-omits-override-only-module-inputs` `#3`). Compile-checked with UBT `-SingleFile` on UE 5.8: `TestNIRGraphLinkCoverage.cpp` and `TestNIRDecompiler.cpp` Succeeded. Not run.
