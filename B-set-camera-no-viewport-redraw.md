# editor.set_camera invalidates but never force-redraws; captured screenshots stay stale

`editor.set_camera` returns `{success:true}` but a subsequent `HighResShot` capture returns the PIXEL-IDENTICAL stale frame regardless of the new camera params. Only `editor.focus_actor` produced a fresh frame, so the capture path works — set_camera just isn't reflected before the shot reads the buffer.

Source confirms the gap (`ViewportHandler.cpp`):
- `set_camera` (L106-119) takes the subsystem path: `UUnrealEditorSubsystem::SetLevelViewportCameraInfo()` then `ULevelEditorSubsystem::EditorInvalidateViewports()`. That only marks the viewport *dirty*; it does not force a synchronous `Draw()`. With realtime capture timing the `HighResShot` grabs the buffer before the next redraw, yielding the stale frame.
- `focus_actor` (L71-74) instead runs `GEditor->Exec("EDITORTEMPVIEWPORT")` + `MoveViewportCamerasToActor()`, which touch the level viewport client(s) and force an immediate redraw — hence a fresh frame.

So this is NOT a missing-invalidate bug (set_camera does invalidate) and NOT the screenshot completion-signal bug (`B-editor-screenshot-no-completion-signal`, already DONE) — it is a missing *force-redraw* before the capture observes the frame.

**Workaround:** call `editor.focus_actor` (or any handler that runs `MoveViewportCamerasToActor`/`EDITORTEMPVIEWPORT`) after set_camera to force a redraw before screenshotting.
**Fix:** after `SetLevelViewportCameraInfo`, resolve the active perspective level-editor viewport client and call `Invalidate(true, true)` + `ViewportClient->Viewport->Draw()` (or `GEditor->RedrawLevelEditingViewports(true)`) so the new camera is rendered synchronously before control returns. Also confirm the targeted client matches `GEditor->GetActiveViewport()` used by the capture path.
