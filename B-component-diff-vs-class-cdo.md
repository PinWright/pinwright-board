# scs.json diffs component template against class CDO instead of parent template

For each SCS node, the property diff base is `Node->ComponentTemplate->GetClass()->GetDefaultObject()` — the bare component class CDO. This is wrong for inherited components.

If a parent BP defines an SCS node with `StaticMesh = SM_Fuselage`, and a child BP adds a local SCS node overriding only `CastShadow = false`, the child's `scs.json` will report both `StaticMesh = SM_Fuselage` and `CastShadow = false` as overridden — the mesh was inherited, not changed. This bloats the dump and misleads consumers into thinking every parent-set value is a local override.

The correct diff base for an SCS node is the same-named component template in the nearest ancestor's SCS, ICH, or native subobjects — falling back to the class CDO only when no parent template exists.

**Fix:** For each SCS node, walk `Blueprint->ParentClass` up the hierarchy. For each level, if the parent class was generated by a Blueprint, look up the same-named node in `ParentBP->SimpleConstructionScript->FindSCSNode(VariableName)`. Use that node's `ComponentTemplate` as the diff base. If not found, continue up the chain. If exhausted, fall back to the class CDO.

## History
- `#1-initial-repro` `OPEN` reporter — scs.json uses component class CDO as diff base, causing parent-inherited property values to appear as local overrides on child BPs; diff is misleading and bloated.
- `#2-resolve-parent-template` `IN-REVIEW` developer — Fixed diff base resolution in `GetBlueprintSCS` (EditorAutomationRpcGateway_SCSHandlers.cpp) via new `ResolveParentTemplate` static helper. For each SCS node, the helper walks `Blueprint->ParentClass` chain, finds the matching SCS node by variable name in each parent BP's SCS, and returns its `ComponentTemplate`. Falls back to class CDO when no parent template is found. The same `ResolveParentTemplate` logic is used for native and ICH entries.
- `#3-cache-parent-templates` `IN-REVIEW` developer — Per shortcut-audit: replaced per-call chain walk with one-shot `BuildParentTemplateMap` invoked once before the SCS/ICH loops. `ResolveParentTemplate` now does a single TMap::Find per call. Eliminates O(nodes × depth) overhead.
- `#4-agent-verified-pass` `IN-REVIEW` tester — PASS. Test: `asset.dump` on `/App/HELIOS/Drones/Icarus/Parent/Icarus_ParentBP` (deep inheritance: Icarus_ParentBP → Atlas_ParentBP → HELIOS_BP → C++ ADrone). scs.json properties blocks are sparse — many components have NO `properties` field at all (no overrides vs parent template), and where present, only specific delta values appear (e.g. `bAbsoluteScale: true` on inherited SceneComponents, `OverrideMaterials` only on motors that override the inherited material). Pre-fix this would have shown every parent-set value as a local override, bloating the dump significantly.
- `#5-reverified-this-pass` `DONE` tester — Re-verified during /mcp-review on a fresh dump: of 36 component nodes in Icarus_ParentBP scs.json, only 10 (28%) carry a non-empty `properties` field — 72% have no overrides vs parent template. First 5 nodes inspected: MeshComponent (native, 2 props), CameraHub/PropellerComponent/AudioComponent/ProximityFadeComponent (native, 0 props each). Sparse output confirms parent-template diff base is in effect.
