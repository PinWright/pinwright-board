# BPIR enum parameter syntax inconsistent between compile and decompile

Three different forms exist for the same concept; only the bare form works for compile:

**Compile path:**
- `entry custom_event X(EReplaySaveState NewState)` → works
- `entry custom_event X(enum EReplaySaveState NewState)` → fails with `Could not resolve value '$NewState' for pin '' — variable 'NewState' not found`

**Decompile path:**
- Same compiled event decompiles to `entry custom_event X(enum<EReplaySaveState> NewState)` — third form, accepted by neither path.

Example 11 of `bpir-examples.md` implies (via `float Amount` style) that `enum T Name` should work for enum params.

**Impact:** Round-trip (`decompile → edit → compile`) fails. Agents following examples with enum params hit variable-not-found errors.

**Proposal:** Pick one canonical form. Accept it in the compiler, emit it from the decompiler. Update `bpir-language-reference.md`.
