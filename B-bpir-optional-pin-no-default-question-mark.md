# Disconnected optional pins emit `?` token

When a function or node argument pin is optional, has no incoming
connection, and has no default value in the BP graph, the decompiler
emits `?` at the call site plus a warning
`Unresolvable value: pin '<Name>' has no connection`.

The `?` token is ambiguous in BPIR: it could mean "use this pin's
default" or "omit this argument entirely." If the round-trip compiler
treats `?` as a literal value or fails to parse it, recompiling
produces a broken graph or an error.

194 `bpir.txt` files in the cache hit this. Highest-volume pins:
- `Debug` (181 occurrences)
- `ConcurrencySettings` (116)
- `Instigator` (101)

These are all genuinely optional pins that BP graphs leave unwired
because the engine handles a null default at runtime. The fix is on
the emitter side: detect "optional pin + no connection + no default"
and either omit the argument entirely or emit a sentinel like
`(unset)` that the compiler explicitly skips.

**Repro:** Any BP that calls a function with an unwired optional pin
(e.g. `PlaySoundAtLocation` with `ConcurrencySettings` left blank).

**Workaround:** Manually drop the `?` argument before recompiling.

**Fix (proposed):** In the call-site emitter, check the pin's
`bAdvancedView`/`bDefaultValueIsIgnored` flags and the
`HasAnyConnections()` result. If both indicate the pin should be
omitted, skip it from the arg list entirely and don't emit a warning.

## History
- `#1-initial-audit` `OPEN` reporter — 194 cached `bpir.txt` files contain at least one `?` arg from disconnected optional pins. Top pins: Debug (181), ConcurrencySettings (116), Instigator (101). Round-trip risk if BPIR compiler doesn't accept `?` as omit-arg sentinel.
- `#3-still-emits-question-mark` `OPEN` tester — Live decompile of `/Game/CarConfigurator/Shared/Audio/Ambients/BP_CarReveal_Audio` still emits `ConcurrencySettings: ?` and `OwningActor: ?` at a `PlaySound2D` call site with both pins unconnected and no default. Two warnings fire with the NEW wording ("Optional pin 'X' has no connection or default; omitted at call sites, returns `?` token in positional contexts.") — proving the warning text fix landed and the helper classifies these pins as omittable, yet `FormatArgs` still emitted them as `Name: ?` rather than dropping them. The omission path in `BpirTextEmitter.cpp` is not being taken for named-arg call sites; only the warning softening reached production. `/App/App/UI/W_AppMapEditor` decompile was clean (no `: ?` and no warnings) — likely no qualifying optional pins on those nodes. Old wording check passes (string "has no connection, default value" not present). Re-open: `IsPinOmittableAtCallSite` either is not invoked from the named-arg branch in `FormatArgs`, or its predicate misses the `PlaySound2D` `ConcurrencySettings`/`OwningActor` shape (likely soft-object/object-ref pin where `DefaultObject==null` is treated as "has a default"). Repro asset: `/Game/CarConfigurator/Shared/Audio/Ambients/BP_CarReveal_Audio` event `Play Sound`.
- `#2-omit-vacuous-default-pins` `IN-REVIEW` developer — Broadened the skip filter in `Decompiler/BpirTextEmitter.cpp` `FormatArgs` via a new file-local helper `IsPinOmittableAtCallSite(UEdGraphPin*)` that drops unconnected pins with no `DefaultObject`, no `DefaultTextValue`, and a default value that is empty / `None` / matches the autogenerated value. Exec pins and `self` are excluded from omission. `EmitVariableSet` deliberately untouched — it has its own single-pin path that wants `set Var = ?` for round-trip. In `Decompiler/BpirDecompiler.cpp` softened the catch-all warning at the end of `ResolveInputValue` (now at lines ~1643-1648 after T2's tunnel-branch insertion) from "Unresolvable value: pin 'X' has no connection, default value, or default object" to "Optional pin 'X' has no connection or default; omitted at call sites, returns `?` token in positional contexts." — the function still returns `TEXT("?")` so branch/switch/return callers retain a token. No parser/compiler changes needed; `BpirParser::ParseArgs` already skips empty parts. Added regression `FDecompilerOmitsOptionalUnwiredPinsTest` in `TestDecompiler.cpp` that builds `BeginPlay -> PrintString` with all optional pins unwired, calls production `FBpirDecompiler::Decompile`, and asserts `Result.BpirText` does not contain `": ?"`, `Result.BpirText` contains `"PrintString"`, and no warning uses the old "has no connection, default value" wording. Files touched: `BpirTextEmitter.cpp`, `BpirDecompiler.cpp`, `TestDecompiler.cpp`. Header `BpirTextEmitter.h` left untouched (helper stayed file-local to minimize churn).
- `#4-broaden-object-ref-predicate` `IN-REVIEW` developer — Root cause: `UEdGraphPin::DoesDefaultValueMatchAutogenerated()` returns false for object-ref pins (PC_Object/PC_Class/PC_Interface/PC_SoftObject/PC_SoftClass) when `Pin->DefaultValue == "None"` because the engine's catch-all (`EdGraphSchema_K2.cpp:4993-5079`) falls through to `IsDefaultAsStringEmpty()` which rejects `"None"`. The prior `IsPinOmittableAtCallSite` helper's `!= "None"` exception only covered the DefaultValue side; the symmetric autogenerated-side variant slipped through. Fix: in `Decompiler/BpirTextEmitter.cpp::IsPinOmittableAtCallSite`, added an explicit object-ref short-circuit: for PC_Object/PC_Class/PC_Interface/PC_SoftObject/PC_SoftClass categories with `DefaultObject==nullptr`, empty `DefaultTextValue`, and `DefaultValue` in `{"", "None"}`, return true without consulting `DoesDefaultValueMatchAutogenerated`. Promoted helper from file-static to `BpirTextEmitterInternal` namespace declared in the existing `Private/Decompiler/BpirTextEmitter.h` so tests reach production code directly (test module already covers `Private/` via PrivateIncludePaths). New regression test `FDecompilerOmitsOptionalObjectRefUnwiredPinsTest` in `TestDecompiler.cpp` builds `BeginPlay -> PlaySound2D` with `ConcurrencySettings`/`OwningActor` unwired, drives production `FBpirDecompiler::Decompile`, asserts `ConcurrencySettings: ?`/`OwningActor: ?` are absent and that the helper directly returns true on those pins. Existing `FDecompilerOmitsOptionalUnwiredPinsTest` retained for primitive coverage. Files: `BpirTextEmitter.cpp`, `BpirTextEmitter.h`, `TestDecompiler.cpp`.
- `#5-verify-fix` `DONE` tester — Verified: live `blueprint.decompile` on `/Game/CarConfigurator/Shared/Audio/Ambients/BP_CarReveal_Audio` returned BPIR for `Play Sound` event containing `call PlaySound2D(Sound: $Sound, VolumeMultiplier: 1.000000, PitchMultiplier: 1.000000, StartTime: 0.000000, bIsUISound: true)` — no `ConcurrencySettings: ?` or `OwningActor: ?` arguments, and `warnings` array is empty.
