# BPIR function resolver ignores DisplayName/ScriptName meta

`FCodeFunctionResolver::ResolveFunction` (`Source/PinWright/Private/Compiler/CodeFunctionResolver.cpp:80`) matches a member UFUNCTION by three axes only: exact internal FName (`FindFunctionByName`, line 93), a hardcoded alias table (line 100, populated lines 34-65), and a case-insensitive space-stripped pass over `It->GetName()` (lines 114-144). `GetName()` returns the internal/script FName — never the `meta=(DisplayName=...)` or `meta=(ScriptName=...)` shown to authors. So the BP-editor-visible name fails to resolve when it differs from the internal name by anything other than spacing.

Canonical case: `AActor::K2_GetComponentsByClass` declares `meta=(DisplayName="Get Components By Class", ScriptName="GetComponentsByClass")` (`UE_5.6/.../GameFramework/Actor.h:3762`). Authoring `call GetComponentsByClass(Target: self, ...)` fails — the space-stripped fallback compares the needle against `k2_getcomponentsbyclass` (the `K2_` prefix survives stripping), so it never matches. Only the internal `K2_GetComponentsByClass` resolves. Agents author against the BP-visible name, forcing them to guess internal C++ names. The hardcoded alias table (e.g. `DestroyActor → K2_DestroyActor`, line 52) is the current band-aid — proof the gap is being papered over one entry at a time instead of reading the meta systematically.

**Workaround:** call the internal FName directly — `call K2_GetComponentsByClass(Target: self, ComponentClass: ...)` compiles (verified, nodeCount:8). For other functions, decompile an existing node or check `blueprint.inspect` to discover the `K2_`/internal name.

**Fix:** add a fourth resolution pass in `ResolveFunction` after the space-stripped fallback: iterate `TFieldIterator<UFunction>` and compare the needle (case-insensitive, optionally space-stripped) against each candidate's `GetMetaData("DisplayName")` and `GetMetaData("ScriptName")`. One match returns it; multiple matches warn + return nullptr (mirror the existing ambiguity handling at lines 132-143). Prefer this over growing the hardcoded alias table.
