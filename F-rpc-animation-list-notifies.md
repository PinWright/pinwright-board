# Add live RPC `animation.authoring.list_notifies` returning per-notify name/time/duration/branchingPoint

`AnimSequenceDumpBuilder::BuildAnimSequenceJson` (Source/.../Handlers/Asset/AnimSequenceDumpBuilder.cpp) emits a sorted `notifies[]` array on `anim_sequence.json` via the file-local `BuildNotifiesArray` helper (lines 29-72): per entry it walks `Sequence->Notifies` (a `TArray<FAnimNotifyEvent>`) and writes `name` (`Event.NotifyName.ToString()`), `time` (`Event.GetTime()`), `duration` (`Event.GetDuration()`), and `branchingPoint` (`Event.IsBranchingPoint()`), then sorts by `(time, name)` for stable output.

Live animation RPCs cover none of this. `animation.authoring.get_animation_info` (AnimationAuthoringHandler.cpp:3320) returns `numNotifies` as a count only — never the array. Writers exist on both namespaces (`animation.add_notify` in AnimationHandler.cpp:1158 — simple AnimSequence-only path; `animation.authoring.add_notify` at AnimationAuthoringHandler.cpp:609, plus `animation.authoring.add_notify_state` and `animation.authoring.add_montage_notify`) but no reader. Confirmed by grepping `Source/` for `list_notif`, `get_notif`, `enumerate_notif`, and `REGISTER_RPC_HANDLER\("animation\.` — no live notify reader exists in either namespace.

This violates the asset-dump-parity policy (anything a dump emits must also be reachable via a live MCP RPC). It also blocks every inspect-after-mutate workflow: an agent that just ran `animation.authoring.add_notify` / `add_notify_state` cannot read back what it wrote without re-running `asset.dump` and parsing the sidecar, which is slow and stale by the time the next mutation lands. The bumped `numNotifies` count from `get_animation_info` is not enough — agents need names and times to know whether their write landed at the intended position and whether duplicate names exist.

**Fix:** Add `animation.authoring.list_notifies` (params: `assetPath`) next to `add_notify`/`add_notify_state` in AnimationAuthoringHandler.cpp. Resolve via `NormalizeAnimPath` + `StaticLoadObject<UAnimSequenceBase>` so it covers both `UAnimSequence` and `UAnimMontage` (both extend `UAnimSequenceBase`, both expose `Notifies`). For shape parity the handler should reuse the dump's notify shape directly — simplest path is to either (a) export the existing `BuildNotifiesArray` helper from `AnimSequenceDumpBuilder.h` (currently anonymous-namespace) and call it, or (b) iterate `Asset->Notifies` inline using the same four field names (`name`, `time`, `duration`, `branchingPoint`) and the same `(time, name)` sort. Option (a) is preferred to prevent schema drift. Place the writer's namespace partner (`animation.authoring.list_notifies`) rather than `animation.add_notify` — the elaborate authoring writers (notify states, montage notifies) and `get_animation_info` already live there, so the reader belongs alongside them.
