# A failed CRIR compile leaves cleared graphs and partial hierarchy/function edits

Replace resolves a model and controller, calls `ClearGraphForReplace`, then begins emission (`Plugins/PinWright/Source/PinWright/Private/CRIR/CRIRCompiler.cpp:187-201, 448-489`). The clear snapshots all nodes and removes each with `bSetupUndoRedo=false` (`:79-96`). A valid CRIR document can then name a nonexistent unit struct; `AddUnitNodeFromStructPath` fails and returns `CRIR_UNIT_CREATE_FAILED` (`:349-384`) after the graph has already been erased. Later instruction failures likewise leave earlier additions.

The outer `FScopedTransaction` and `ModifyControlRigBlueprint` (`CRIRCompiler.cpp:1470-1472`) do not undo on scope exit. All graph/controller edits explicitly disable per-call undo, and every pass returns immediately on failure (`:1517-1557`) without `Cancel`, editor undo, or explicit restore. Pass 1 can also add hierarchy elements or functions before a Pass-2 graph error. `controlrig.compile_crir` only forwards that error (`Handlers/ControlRig/CRIRCompileHandler.cpp:69-73`). The caller sees failure while the live rig is cleared/partial, and a later save can persist it.

Preflight all model, struct, function, hierarchy-parent, and wire references before the first edit. Then snapshot the RigVM models, hierarchy, and local function library and use the established transaction rollback shape (`PrepareTransactionalSnapshot`, finalized transaction, `ApplyAndCancelTransaction`) on every failed pass. Verify post-rollback topology and hierarchy against the snapshot. Extend must also remove its partial additions.

**Workaround:** compile only into a disposable duplicate; after an error, reload the original package from disk before any save.

## Fix

The compiler opened a transaction but snapshotted only the Control Rig Blueprint while RigVM controllers mutated graph-owned objects and the hierarchy with their own undo disabled. Its three failure exits after the transaction returned directly, so the scoped transaction was committed instead of applied and canceled. The fix snapshots the Blueprint and hierarchy and records the pre-existing RigVM graphs/nodes for cleanup, while leaving graph-owned objects out of the editor transaction. Replace-mode clearing uses one public action-backed `URigVMController::RemoveNodes(..., true, false)` call; RigVM's `FRigVMRemoveNodesAction` serializes the baseline nodes and exterior links so its action-stack undo is the sole graph restoration owner, instead of letting editor property undo restore graph arrays containing objects already renamed and marked as garbage. On failure it disables automatic VM recompilation and asset notifications, guards controller notifications while removing failed-attempt nodes and applying the transaction undo, then calls the public `URigVMController::RemoveStaleNodes()` on every restored model/controller before restoring the notification path. It releases the controller guards, rebinds every surviving `URigVMEdGraph` with its public `InitializeFromAsset` API, and only then resumes asset notifications so the engine can rebuild the EdGraph mirror from the valid model, then restores the prior auto-recompile setting and performs one deferred VM recompile only after the model and editor mirror are clean. The package's original clean state is restored.

Known limitation: rollback requires the editor transactor used by the normal `UnrealEditor` and `UnrealEditor-Cmd` automation hosts. A true commandlet environment without `GEditor->Trans` reaches `ApplyAndCancelTransaction`'s cancel-only fallback, which cannot restore the already-mutated model; the regression test deliberately skips that unsupported environment instead of simulating it.

Deliberately not changed: CRIR parsing/preflight rules, successful compile behavior, save behavior, and the sibling AGIR compiler. Complete preflight could improve error timing, but rollback is still required for controller failures that cannot be proven statically.
